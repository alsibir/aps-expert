## Сквозной пример: регистрация обращения

Исходная задача — принимать обращения, проверять обязательные сведения, передавать их на рассмотрение и уведомлять участников. Для аналитического описания требуется определить автора обращения, ответственного исполнителя, допустимые состояния и поведение при ошибках.

| Уровень описания | Что должно быть зафиксировано |
| --- | --- |
| Пользовательская цель | Зарегистрировать обращение и получить его идентификатор |
| Бизнес-правило | Неполное обращение не должно переходить к обработке |
| Сценарий | Заполнение, проверка, сохранение, подтверждение; отдельное описание ошибок |
| Данные и интерфейсы | Обязательные поля, формат запроса, ответ и сообщения об ошибках |
| Проверка | Положительный и отрицательный сценарии с наблюдаемым ожидаемым результатом |

Сопоставление моделей и документов позволяет проверить, одинаково ли описаны роли, статусы и ограничения. Графический альбом служит обзором решений, а не доказательством работы программного продукта.
